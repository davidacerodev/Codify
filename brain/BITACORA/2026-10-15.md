## Protección de borrado físico

- Se cambió el comando interno de inventario a `medication.archive` y el texto de interfaz/historial a “retirar del catálogo”; no hay una operación HTTP de borrado.
- Si falla el alta de perfil después de crear la identidad Auth, el servidor la bloquea y conserva. La prueba local indujo documento duplicado, recibió 409 y verificó que la identidad quedó bloqueada sin perfil.
- Se añadió `20261015000000_preserve_operational_records.sql`, con triggers que rechazan `DELETE` en perfiles, medicamentos, lotes, citas, despachos, ítems, auditoría y horarios. El Supabase local rechazó borrar una cita y eliminar una identidad Auth en cascada; ambos registros permanecieron.
- `db push --linked --dry-run` mostró solo esta migración nueva. Se aplicó al Supabase remoto y `migration list --linked` confirmó las cuatro versiones. El cambio fue de esquema; no se escribieron ni borraron registros de negocio remotos.
- Tras la protección, la integración completó 11 pruebas API/RPC y restableció Supabase local; la suite UI completó 17 recorridos, `npm run check` terminó sin errores (siete advertencias de hooks) y seguridad API completó 10 comprobaciones.
- Se creó `docs/api/GUIA_ENDPOINTS.md` como borrador de contrato y `PLAN_TRABAJO/VALIDACION_ENFERMERIA.md` con preguntas y casos clínicos pendientes de aceptación.
